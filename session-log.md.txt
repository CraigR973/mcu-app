### Decisions / Notes

**`%(here)s` in `alembic.ini`** — `script_location = migrations` resolves relative to CWD, not to `alembic.ini`. Using `%(here)s/migrations` (Alembic's built-in variable for the ini file's directory) makes it work when run from any directory.

**`DATABASE_URL` from Settings, not `alembic.ini`** — `env.py` calls `config.set_main_option("sqlalchemy.url", settings.database_url)` at import time. Credentials stay in `.env.local` (gitignored) and never touch the ini file.

**`psycopg2-binary` for sync migrations** — Alembic runs synchronously; `asyncpg` is not compatible. `psycopg2-binary` is the right driver here. `asyncpg` can be added later for async FastAPI routes if needed.

**`raise_app_exceptions=False`** — `ASGITransport` propagates unhandled server exceptions to the test by default, causing the 500 test to raise instead of returning a response. **SSH key setup** — Remote was HTTPS-only with no stored credentials. Generated `~/.ssh/github` (ed25519), added to GitHub, updated `~/.ssh/config`, switched remote to `git@github.com:CraigR973/mcu-app.git`.

### Decisions / Notes

**`soft_delete()` trigger pattern** — A `BEFORE DELETE` trigger intercepts `DELETE` statements and executes `UPDATE SET deleted_at = NOW() WHERE id = OLD.id AND deleted_at IS NULL`, then returns `NULL` to cancel the actual delete. Applied to `collection_items` and `wanted_list`. `price_checks` and `price_history_daily` are append-only audit tables and don't need soft delete.

**`price_checks → wanted_list` FK** — `ON DELETE SET NULL` so deleting a wanted item doesn't cascade-destroy its price history; the check records remain linked only to their movie.

**`price_history_daily` UNIQUE constraint** — `(movie_id, format, source, date)` enforces exactly one daily rollup row per combination, enabling safe `INSERT … ON CONFLICT DO UPDATE` upserts from the price aggregation job.

**Migrations applied to live Supabase** — `upgrade head` ran successfully; 0003 and 0004 applied on top of existing 0001/0002.

**CI failures fixed** — Two ruff failures post-push: `E501` (line too long in CHECK string, wrapped with implicit string concatenation) and `ruff format --check` (whitespace normalization). Three commits total to reach green.

## Phase 1.6 Session Log
Date: 2026-04-26 | Model: Opus 4.7 | Commits: 6428f36 (initial), 9394095 (live-eval tuning) — both CI green
Added `search_movie()` to TMDBClient (year filter, page, language, include_adult) plus SearchResult/SearchResults Pydantic models exposing a `year` property derived from release_date. Created src/matching package with MatchingEngine, MatchCandidate, MatchResult and a pure-function pipeline. Engine sorts by (confidence desc, popularity desc), caches by canonicalised (title, year), and retries without the year filter when a year-scoped search returns zero results.

**Initial scorer:**
- extract_year() peels trailing "(YYYY)"
- title_similarity() runs difflib.SequenceMatcher on canonicalised strings, falls back to original_title when higher
- score() blends similarity with year bonuses (+0.15 exact, +0.05 close ±1y, -0.30 mismatch) capped to [0, 1]
- HIGH_CONFIDENCE = 0.85 (matched flag), LOW_CONFIDENCE = 0.6 reserved for future review-bucket use

**Live-eval tuning (commit 9394095):** First eval against 100 sampled spreadsheet titles hit only 70/100 confident. Three high-leverage fixes lifted the score to 92/100:
1. **Trailing-article rotation** — rotate_trailing_article() rewrites library-card titles like "Eiger Sanction, The" → "The Eiger Sanction", "Meg the" → "The Meg", "Hitman's Bodyguard The" → "The Hitman's Bodyguard" before searching TMDB. Trailing word must be the/a/an, so titles ending in other words ("The Last Jedi", "I Am Legend") are untouched. This single fix recovered ~13 misses.
2. **Annotation stripping** — strip_annotations() drops "[...]" and "(...)" tags ("[Ealing Classics Collection]", "(Boxset with The Italian Job)", "(Unico Testigo)") that were poisoning TMDB search.
3. **Edition-suffix stripping** — strip_edition_suffix() peels trailing edition / cut markers ("The Final Cut", "Director's Cut", "Extended Edition", "Remastered", ...) so "Blade Runner The Final Cut" searches as "Blade Runner".
4. **Apostrophe collapse + substring containment floor** in title_similarity(): apostrophes are removed (not replaced with space) so "National Lampoons" canonicalises identically to "National Lampoon's"; when the query is fully contained in the result title (or vice versa) similarity is floored at 0.9, lifting partial matches like "Vampire's Assistant" inside "Cirque du Freak: The Vampire's Assistant".

normalise_query() chains these in order: extract_year → strip_annotations → strip_edition_suffix → rotate_trailing_article. 118 unit tests cover each transform and the engine end-to-end.

**Acceptance result:** 92/100 confident matches on live TMDB (target ≥90). The 8 remaining misses are flagged correctly per spec: typos (Grindewald, Sory), TV series (Steptoe & Son, Bonekickers), "Ep VIII" prefix ("Star Wars Ep VIII - The Last Jedi"), separator quirk ("Cowboys v Aliens"), and sequel-numbering ("Dune 2" vs "Dune: Part Two", "Ice Age 3" vs "Ice Age: Dawn of the Dinosaurs"). These are inherently ambiguous and belong in the human-review bucket Phase 1.7 will produce.

**Eval harness:** `apps/api/scripts/eval_matching.py` runs the engine against a sampled subset of the real spreadsheet and writes a CSV. Invoke with `set -a; source apps/api/.env.local; set +a` first so the TMDB token loads — pydantic-settings only reads `.env`, not `.env.local`.

No new runtime deps — uses stdlib difflib.
